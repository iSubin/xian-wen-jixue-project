# Git / Obsidian 双端知识库目录设计

状态：已实现
日期：2026-08-09

## 1. 设计目标

Git 仓库是用户拥有的云端知识库，Obsidian clone 是本地阅读与继续写作的工作台。默认产物必须少、稳定、可直接阅读，不把任务状态、模型参数和处理中间数据暴露成大量文件。

目录设计同时支持三个概念：

- `内容/`：一份内容唯一、稳定的正文资产。
- `藏经阁/`：当前树状分类，通过索引链接组织内容。
- `专题/`：后续多对多专题管理，同样引用内容，不复制正文。

## 2. 仓库结构

```text
<用户配置的文库根目录>/
  内容/
    <原始内容标题>/
      <原始内容标题>.md
      原始逐字稿.md          # 音频、视频
      原始正文.md            # 文章、网页，仅与逐字稿二选一
      assets/                # 仅保存正文实际引用的图片与截图
  藏经阁/
    _索引.md
    <一级目录>/
      _目录.md
      <二级目录>/
        _目录.md
  专题/                      # 专题功能启用后创建
  _索引.md
  .xianwen-manifest.json
```

主文档和内容目录使用同一个原始标题，兼容 Obsidian Folder Note 的使用习惯。文章只生成 `原始正文.md`，音视频只生成 `原始逐字稿.md`；关闭“附带原始转写”后只生成主文档。

## 3. 为什么正文不跟随藏经阁目录移动

藏经阁是一棵分类树，专题则是多对多关系。同一份内容未来可能同时属于多个专题。如果把正文直接放入分类或专题目录，就会产生复制、路径移动和 WikiLink 失效。

因此：

- 正文路径只由原始标题决定。
- 藏经阁移动只更新 `_目录.md` 中的链接。
- 专题新增或删除只更新专题索引。
- 正文、附件和原始材料始终只有一份。

## 4. 标题与路径规则

1. 优先使用来源提供的 `title`，不使用 AI 生成的 `topic` 替换原始标题。
2. 只清理文件系统不允许的字符，保留中文、空格和可用标点。
3. 同名内容中，最早内容保留原标题；后续内容追加 `__<8 位内容 ID>`。
4. 首次发布后，目录名写入 `.xianwen-manifest.json`，后续整理稿标题变化不移动正文。
5. 本地 `file://` 绝对路径不写入 Git 文档。

## 5. 文件所有权与冲突

先闻继学只管理 manifest 中登记的文件：

- 内容目录里由用户新增的 `我的笔记.md`、批注和附件不会被删除。
- 受管文件在 Obsidian 中被修改后，下一次同步保留用户版本并报告冲突。
- 从藏经阁移除内容时，只删除仍与上次发布 hash 一致的受管文件；用户修改或新增的文件继续保留。
- Git 到数据库的反向导入不属于当前范围，不能把冲突保护描述成完整双向同步。

## 6. 自动归档生命周期

```text
采集任务完成
  -> 标记 Git 文库 pending_sync
  -> 2 秒防抖，合并批量采集更新
  -> 临时 clone 目标分支
  -> 生成内容与藏经阁索引
  -> manifest 冲突检查
  -> commit / push
  -> connected 或 error
```

自动归档与采集任务解耦。Git 网络、权限或冲突错误只写入 Git 账号状态，不把已经完成的采集任务改为失败；用户可以在设置中关闭自动归档或手动重试整库同步。

## 7. Deploy Key 边界

- 用户在目标 Git 仓库创建专用 Deploy Key，并显式开启写权限。
- 先闻继学只接受 SSH 仓库地址，私钥加密保存在本机数据库，API 不返回明文。
- 同步时私钥只写入权限为 `0600` 的临时文件，临时 clone 结束后随目录清理。
- Deploy Key、Cookie、模型密钥、临时签名 URL 和本地绝对路径不得进入文库内容。
